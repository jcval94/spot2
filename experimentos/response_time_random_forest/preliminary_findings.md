# Preliminary multivariable finding

A lightweight Random Forest replication was run directly against the repository data to sanity-check the hypothesis before the canonical scikit-learn workflow executes.

## Immediate inquiry target

On 19,178 inquiries with measured response time, adding response hours to a multivariable forest did not improve the temporal test set in the lightweight replication:

- base AUC: ~0.513
- + response hours AUC: ~0.497
- permutation AUC drop for response hours: ~-0.003
- global 2h vs 36h counterfactual model difference: approximately 0.0 percentage points

This is consistent with the earlier observation that response-time buckets were almost flat.

## First response -> later visit within 30 days

A second, more product-relevant target used only the first inquiry per lead and asked whether a later inquiry became a scheduled visit within 30 days, excluding the first inquiry itself.

Eligible sample: 4,063 leads.

In the lightweight forest:

- base AUC: ~0.516
- + response hours AUC: ~0.526
- response hours received ~3.4% impurity importance and appeared in many tree branches
- but permutation importance was essentially zero / slightly negative
- setting every case to 2h instead of 36h changed mean model probability by only ~+0.33 percentage points

The strongest subgroup counterfactual differences were still small, roughly around half a percentage point. For example, email leads showed about +0.5 pp modeled difference for 2h vs 36h.

## Interpretation

This is exactly why the canonical experiment uses both tree importance and permutation importance.

The Random Forest can split on a continuous response-time feature frequently, especially in deeper branches, while the feature still provides little stable out-of-sample information. If the full scikit-learn run confirms that pattern, response time should be treated as an operational SLA variable to test causally, not as a strong predictive driver in the provided synthetic data.

These values are a preliminary replication; canonical metrics are generated by `run_experiment.py`.
